# Корпоративный банк идей

Веб-приложение для сбора и обработки идей сотрудников: сотрудники подают идеи, руководители их рассматривают и согласовывают, эксперты реализуют, администратор управляет пользователями и справочниками. Django + PostgreSQL + htmx — сервер отдаёт готовый HTML напрямую, без отдельного фронтенд-приложения.

Ниже — два независимых способа установки. Прочитайте оба заголовка и выберите тот, что подходит именно вам — дальше не нужно возвращаться к другому разделу, каждый способ доведён до конца самостоятельно.

- **Способ 1** — если у вас есть ссылка на репозиторий на GitHub (или другом Git-хостинге) и установлен Git.
- **Способ 2** — если вам прислали проект файлом (архивом), без доступа к Git вообще.

## Что нужно перед началом (для обоих способов)

| Требование | Зачем | Проверить установку |
|---|---|---|
| Python 3.12 или новее | сам язык, на котором написано приложение | `python --version` |
| Docker Desktop | локальная база данных PostgreSQL в изолированном контейнере — если ещё не установлен, подробная установка ниже | `docker --version` |
| Git — только для Способа 1 | получение кода из репозитория | `git --version` |

Если `docker --version` выдаёт ошибку «команда не найдена» — переходите к разделу ниже, он закрывает именно эту ситуацию.

## Установка Docker Desktop (если ещё не установлен)

Docker нужен для локальной базы данных PostgreSQL в обоих способах установки. Если он уже стоит и запускается — пропустите этот раздел и переходите сразу к выбранному способу.

### Windows

1. **Системное требование:** Windows 10/11, 64-битная версия, с включённой поддержкой WSL2 (Windows Subsystem for Linux) — при установке Docker обычно предлагает включить её сам, если ещё не включена.
2. Скачать установщик с официального сайта: **https://www.docker.com/products/docker-desktop/** → кнопка «Download for Windows».
3. Запустить `Docker Desktop Installer.exe`, пройти мастер установки. Галочка **«Use WSL 2 instead of Hyper-V»** должна остаться включённой — это значение по умолчанию и рекомендуемый вариант, менять не нужно.
4. Если WSL2 ещё не установлена, установщик сам предложит её поставить. Если понадобится сделать это вручную — открыть **PowerShell от имени администратора** и выполнить:
   ```powershell
   wsl --install
   ```
   затем перезагрузить компьютер.
5. После установки Docker Desktop обычно тоже просит перезагрузить компьютер — сделать это, если предложит.
6. Запустить Docker Desktop из меню Пуск. При первом запуске — принять лицензионное соглашение; вход в аккаунт Docker Hub **не обязателен**, можно нажать «Skip» / пропустить.
7. Дождаться, пока в самом приложении появится статус **«Docker Desktop is running»**, а значок кита в системном трее (рядом с часами) перестанет анимироваться — только после этого Docker готов к использованию.

### macOS

1. Скачать установщик с **https://www.docker.com/products/docker-desktop/** — выбрать версию под свой процессор (Apple Silicon или Intel; если не уверены — меню Apple в левом верхнем углу экрана → «Об этом Mac» покажет тип процессора).
2. Открыть скачанный `.dmg`, перетащить значок Docker в папку Applications.
3. Запустить Docker из Applications. При первом запуске система спросит разрешения — подтвердить.
4. Дождаться статуса **«Docker Desktop is running»** в строке меню сверху экрана.

### Linux

Способ установки зависит от конкретного дистрибутива — официальная, всегда актуальная инструкция: **https://docs.docker.com/desktop/install/linux-install/**

После установки стоит добавить своего пользователя в группу `docker`, чтобы не требовалось `sudo` перед каждой командой:
```bash
sudo usermod -aG docker $USER
```
и перелогиниться (выйти и снова войти в систему), чтобы изменение вступило в силу.

### Проверка, что всё установилось верно

```bash
docker --version
docker ps
```

Первая команда должна вывести номер версии. Вторая — пустую таблицу (заголовки колонок без строк) или список уже существующих контейнеров, но без ошибки о недоступности — если видите ошибку про то, что Docker не отвечает, само приложение Docker Desktop ещё не запущено или не до конца загрузилось (см. также раздел «Возможные проблемы» ниже).

### Про настройки

Специальные настройки Docker Desktop для этого проекта не нужны — используются стандартные значения по умолчанию (выделенная память, процессор, диск). Ничего в настройках менять не требуется, обычной установки достаточно.

### Если ставить Docker совсем не хочется

Можно обойтись без него — установить PostgreSQL напрямую: скачать с **https://www.postgresql.org/download/**, при установке создать базу данных с именем `bank_idey` (пользователь по умолчанию — `postgres`, пароль задаётся в процессе установки). Дальше все шаги ниже такие же, только шаг «Поднять базу данных» (через `docker run`) не выполняется — вместо этого используются параметры уже установленной локальной PostgreSQL в файле `.env`.

## Способ 1. Через Git

### 1. Клонировать репозиторий

```bash
git clone https://github.com/<логин>/<репозиторий>.git
cd <репозиторий>
```

Скачивает весь код проекта в новую папку с тем же именем, что и репозиторий, и сразу переходит в неё.

### 2. Виртуальное окружение

Изолирует зависимости именно этого проекта от остальных, установленных на компьютере.

**Windows (cmd):**
```cmd
python -m venv venv
venv\Scripts\activate.bat
```

**macOS / Linux:**
```bash
python3 -m venv venv
source venv/bin/activate
```

После активации в начале строки терминала должно появиться `(venv)` — признак, что дальнейшие команды выполняются внутри изолированного окружения, а не в системном Python.

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

Ставит Django и три вспомогательных пакета (django-filter, psycopg2-binary, python-dotenv) — версии зафиксированы в самом файле, чтобы у всех получилось одинаковое окружение.

### 4. Поднять базу данных

```bash
docker run --name bank-idey-db -e POSTGRES_PASSWORD=devpassword -e POSTGRES_DB=bank_idey -p 5432:5432 -d postgres:16
```

Скачивает (при первом запуске) и запускает PostgreSQL 16 в отдельном контейнере, никак не затрагивая остальную систему. Проверить, что контейнер поднялся:
```bash
docker ps
```
В списке должна быть строка с `bank-idey-db` и портом `0.0.0.0:5432->5432/tcp`.

### 5. Настроить переменные окружения

Скопируйте образец в рабочий файл:

**Windows (cmd):**
```cmd
copy .env.example .env
```

**macOS / Linux:**
```bash
cp .env.example .env
```

Откройте `.env` любым текстовым редактором и замените `SECRET_KEY` на собственную случайную строку — сгенерировать можно так:
```bash
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

Остальные значения в `.env` (пароль от базы, имя базы) можно оставить как есть, если использовали команду из шага 4 без изменений.

### 6. Применить миграции

```bash
python manage.py migrate
```

Создаёт все таблицы в базе данных по описанию моделей — без этого шага база останется пустой, и приложение не запустится.

### 7. Создать администратора

```bash
python manage.py createsuperuser
```

Спросит логин, (необязательный) email и пароль — это ваша личная учётная запись с ролью «Администратор». Пароль нигде не восстанавливается, только сбрасывается заново (`python manage.py changepassword <логин>`), если забудете.

### 8. Загрузить демонстрационные данные (по желанию)

```bash
python manage.py seed_demo_data
```

Команду можно запускать повторно — не создаёт дублей. Загружает 2 отдела, 6 демонстрационных пользователей, 3 категории и 10 идей, покрывающих все статусы и роли — удобно для быстрой проверки сценариев, необязательно для самой работы приложения.

### 9. Запустить сервер

```bash
python manage.py runserver
```

Откройте **http://127.0.0.1:8000/** — сработает автоматический переход на страницу входа. Окно терминала с запущенным сервером должно оставаться открытым всё время, пока вы пользуетесь приложением.

## Способ 2. Без Git — если получили проект архивом

### 1. Распаковать архив

Распакуйте присланный файл (`.zip` или похожий) в любую удобную папку — например, через проводник Windows: правая кнопка мыши по архиву → «Извлечь всё».

```bash
cd <папка_с_распакованным_проектом>
```

**Проверка перед началом:** внутри распакованной папки должны быть видны файлы `manage.py`, `requirements.txt`, `.env.example`, и папки `accounts`, `config`, `ideas`, `static`, `templates`. Если видите ещё и папку `venv` или файл `.env` (без `.example`) — их можно смело удалить прямо сейчас: `venv` создастся заново на шаге 2, а `.env` вы создадите сами на шаге 5, со своими значениями, а не унаследованными от того, кто присылал архив.

## Возможные проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `docker` не является внутренней или внешней командой / command not found | Docker Desktop не установлен вообще | См. раздел «Установка Docker Desktop» выше |
| `ModuleNotFoundError: No module named 'django'` | Виртуальное окружение не активировано в этом окне терминала | Выполнить `venv\Scripts\activate.bat` (Windows) или `source venv/bin/activate` (macOS/Linux) — строка приглашения должна начаться с `(venv)` |
| `connection to server at "localhost", port 5432 failed: Connection refused` | Контейнер с базой данных не запущен | `docker start bank-idey-db` (если уже создавался раньше) или повторить команду из шага 4; убедиться, что сам Docker Desktop открыт и полностью загружен |
| `failed to connect to the docker API` | Docker Desktop установлен, но не запущен как приложение | Открыть Docker Desktop, дождаться полной загрузки (значок в трее перестаёт «крутиться»), повторить команду |
| Страница `127.0.0.1:8000` не открывается | Сервер (`python manage.py runserver`) не запущен, или окно с ним было закрыто | Запустить заново (шаг 9); окно терминала с сервером должно оставаться открытым всё время работы с приложением |
| Ошибка про `SECRET_KEY` при запуске сервера | Файл `.env` не создан или пуст | Проверить, что `.env` существует рядом с `manage.py` и содержит непустой `SECRET_KEY` (шаг 5) |
